Hardware spec · laser-pain EEG classifier

Pain Classifier RTL Pipeline

Every step between the electrodes and the pain class, with the exact arithmetic each step performs, so each one can be mapped to a hardware block. One laser hit goes in, one pain class comes out.

Source of truth on main (commit 0760a82): scripts/preprocessing/rich_feature_extraction.py, mvar_features.py, outputs/deploy/deployment_model.json. All weights and coefficients below were generated from those files, not typed by hand.

The whole pipeline in six steps

  1. Capture. When the laser fires, keep a 3-second clip from each electrode: 1 s before the hit and 2 s after (3,000 samples at 1000 per second).
  2. Filter. Pass each clip through band filters. Each filter keeps only one range of brain-wave speeds. Each filter runs forward through the clip, then backward.
  3. Measure. Compute 16 numbers (features) from the filtered clips: wave strengths, the size of the brain's response "dip and bump", and how similar two electrodes are.
  4. Squeeze. Map each of the 16 numbers onto a 0–255 scale (8 bits).
  5. Score. Multiply the 16 values by 48 stored weights and add 3 stored biases. That gives 3 scores: Low, Moderate, High.
  6. Decide. The biggest score is the answer.

Nothing carries over from one laser hit to the next. There is no memory, no neural-network layers and no softmax. The classifier itself is only 48 multiply-and-add operations. Almost all of the hardware effort goes into steps 2 and 3.

Hardware blocks

Where each feature looks in the clip

Stage by stage

1

Trigger and epoch buffer

both
What it does

Keeps the last few seconds from every electrode at all times. When the laser trigger arrives, it freezes a 3-second clip around the hit so the rest of the pipeline can work on it.

Exact maths 
epoch[c][n],  c = channel,  n = 0 … 2999
sample rate      1000 Hz   (1 sample = 1 ms)
laser onset      n = 1000  (clip spans −1.0 s … +1.999 s)
units            microvolts (µV)
Hardware notes
  • The buffer must record continuously, because the clip starts 1 s before the trigger. A circular buffer that freezes about 2 s after the trigger works.
  • Size: 3 channels × 3000 samples (no-MVAR) or 4 × 3000 (fixed). At 24 bits per sample that is 216 or 288 kbit, a handful of BRAM36 blocks.
  • Measured on 12 cleaned training subjects, |x| never exceeded 91 µV, and 99% of samples were under 37 µV. A live headset without artifact cleaning sees blinks of several hundred µV, so leave headroom above that.
  • Training rejected any trial whose stored onset was more than 0.51 samples (about half a millisecond) from the expected position. The trigger needs to be sample-accurate.
  • The ADC's least-significant bit must map to a known µV value. The evoked-potential (ERP) features are in µV, so the weights assume that scale.
2

Filter bank

both
What it does

Brain waves come at different speeds. Each filter keeps one speed range and removes the rest. Each filter runs forward through the clip, then backward through the result, so the output is not shifted in time.

Exact maths 
Each filter = 4th-order Butterworth band-pass = 4 "biquads" in series.
One biquad (a small 2nd-order filter step), per sample:
    y[n] = b0·x[n] + b1·x[n−1] + b2·x[n−2] − a1·y[n−1] − a2·y[n−2]

Zero-phase run (scipy sosfiltfilt, default settings):
  1. Pad 27 samples on each end by odd reflection:
       left  pad k = 1…27 :  2·x[0]    − x[k]
       right pad k = 1…27 :  2·x[2999] − x[2999−k]
     → 3054 samples
  2. Forward pass. Each biquad's 2 state values start at zi · (first padded sample),
     where zi = that filter's steady-state constants (4 × 2 numbers, precomputed).
  3. Reverse the result and run the same 4 biquads again. State starts at
     zi · (last forward output).
  4. Reverse again and drop 27 samples from each end → 3000 samples.
Hardware notes
  • One time-shared biquad engine is enough. Every numerator is [1, 2, 1] or [1, −2, 1], which is shifts and adds. Only a1 and a2 need real multipliers, plus one gain multiply in the first biquad. That is about 9 multiplies per sample per pass, so about 55 k per filter run. All 9 runs total about 0.5 M multiplies, roughly 5 ms at 100 MHz with one multiplier. Laser hits are seconds apart.
  • The reverse pass reads the forward output backwards, so you need a 3054-sample scratch buffer per filter run.
  • Precision is the real risk. The delta filter's poles sit only 0.0015 inside the unit circle, and its first-stage gain is 7.7 × 10⁻⁹. Plan on ≥ 32-bit coefficients and state, or floating point, and confirm against the golden model. A cheaper option is to downsample before the slow-wave filters, but that changes the numbers and has to be re-scored in Python first.
  • Don't skip the padding and start-state steps. The delta filter's memory is about 0.66 s, longer than the 0.5 s gap between the clip edge and the first window it feeds.
  • scipy runs each biquad in "transposed direct form II". In fixed point, matching that form makes bit-exact comparison easier.

3

Feature units: 16 numbers per trial

both

The 16 features come from five kinds of unit. Every unit works on samples already sitting in a buffer, so each is a short loop of accumulates followed by one final calculation.

3a · Band power + log both

Plain: how strong one wave band is during one window. Used by 8 features, counting the two ratio features as built on top of it.

P = (1/N) · Σ y[n]²        over the window, y = band-filtered signal
f = ln( max(P, 1e−12) )    natural log
windows:  w0 = [1000, 1300)  w1 = [1300, 1600)   N = 300

ratio features:  f_band_a − f_band_b   (same channel, same window)
  Cz:w0:delta_over_gamma = f(Cz, delta, w0) − f(Cz, gamma, w0)
  Cz:w0:beta_over_delta  = f(Cz, beta,  w0) − f(Cz, delta, w0)   (no-MVAR)
  C4:w0:beta_over_delta  = f(C4, beta,  w0) − f(C4, delta, w0)   (no-MVAR)
  • Hardware: square-and-accumulate (one multiplier), then one log per power value. Logs per trial: 6 (fixed) or 8 (no-MVAR).
  • Compute log₂ with a leading-one detector plus a small lookup table. Then ln x = 0.693147 · log₂ x, and you can fold that constant into the weights. You can also skip the divide by N: ln(Σ) − ln(300) shifts every value by a constant, which can be folded into the quantizer's lower bound.
  • Measured range of P: 0.003 to 430 µV², about 18 bits of dynamic range before the log.

3b · ERP unit: the brain's "dip and bump" both

Plain: about 0.2 s after a laser hit, the signal at Cz dips (N2) and then bumps up (P2). Bigger responses go with more pain. This unit measures 6 things about that shape, all on the Cz 1–30 Hz signal e.

base  = mean e[500 … 999]                 (500 samples, before the laser)
e'    = e − base                          (baseline correction)

N2    = min  e'[1150, 1300)               n2 = index of the FIRST minimum
P2    = max  e'[n2+1, 1550)               searched only after the dip
N2P2  = P2 − N2
N2mean = mean e'[1150, 1250)              (100 samples)
P2mean = mean e'[1250, 1450)              (200 samples)
RMS    = sqrt( mean e'[1000, 1600)² )     (600 samples)
  • You don't need to subtract the baseline from every sample. Accumulate on the raw e and correct at the end. Min, max and means shift by base. For RMS, use Σe'² = Σe² − 2·base·Σe + N·base².
  • That correction also means the unit can run during the reverse filter pass, which produces samples newest-first. Keep a running max of samples seen so far. When a new N2 minimum is found at sample i, the running max at that moment is exactly max e'[i+1, 1550). Use <= when updating the minimum, so the earliest minimum wins, as in numpy.
  • One square root per trial. Measured: |e'| ≤ 55 µV, and Σe² over 600 samples ≤ 3 × 10⁵ µV².

3c · Correlation between two electrodes both

Plain: do two electrodes' slow waves move up and down together? The answer is +1 (perfectly together) through 0 down to −1 (opposite). Fixed uses C3–C4 and Cz–C3; no-MVAR uses C3–C4 only.

x, y = delta-filtered (1–4 Hz) signals of the two channels, samples [1000, 2000)
r = Σ(x−x̄)(y−ȳ) / sqrt( Σ(x−x̄)² · Σ(y−ȳ)² )

single pass, N = 1000:
r = (N·Σxy − Σx·Σy) / sqrt( (N·Σx² − (Σx)²) · (N·Σy² − (Σy)²) )
  • Five accumulators, then one multiply, one square root and one divide per pair. The result doesn't depend on signal scale, so ADC gain doesn't matter here.
  • The single-pass form subtracts large, nearly equal numbers, so give the accumulators wide headroom (N = 1000 adds about 10 bits).

3d · Hjorth mobility no-MVAR

Plain: how fast the signal wiggles compared with how big it is. Computed once, on Cz.

b = Cz broadband (1–45 Hz) signal, samples [1000, 2000)    (1000 values)
d[n] = b[n+1] − b[n]                                       (999 values)
var(v) = (1/count) · Σ (v − mean v)²     population variance
mobility = sqrt( var(d) / var(b) )
  • Single-pass sums for both variances, then one divide and one square root. The counts are 999 and 1000, and they don't cancel exactly. Keep them as written to match Python.
  • The value only ranges from about 0.03 to 0.09, so its weight is large (about 8.5). That is expected.

3e · MVAR band power fixed

Plain: fits a small prediction model to all four electrodes at once, then reads the Cz delta and theta strength out of that model. It produces 2 features, and it is the only reason the fixed variant needs Fz.

1. Take samples [1000, 2000) of all 4 RAW channels (Fz, Cz, C3, C4), not band-filtered.
2. Low-pass and keep every 4th sample: 81-tap Hamming FIR, cutoff 125 Hz,
   centred (zero-phase), zero-padded at the segment edges   → 250 samples at 250 Hz.
3. Subtract each channel's mean.
4. Least-squares model of order 10 (each sample predicted from the last 10, all channels):
     H = 40 × 240 matrix of lagged samples,  T = 4 × 240 targets
     G = H·Hᵀ  (40 × 40),  G += 1e−6 · trace(G)/40 · I
     solve G · X = H · Tᵀ   (40 × 4)  → coefficient matrices A1 … A10 (each 4 × 4)
     Σ = residual covariance (4 × 4)
5. For f = 1, 2, 3 Hz (delta) and 4, 5, 6, 7 Hz (theta):
     A(f) = I − Σk Ak · e^(−j·2π·f·k / 250)      (4 × 4 complex)
     S(f) = A(f)⁻¹ · Σ · (A(f)⁻¹)ᴴ               take the Cz diagonal entry
6. feature = ln( mean of S_Cz(f) over the band's frequencies )
  • Cost per trial: about 190 k multiply-adds to build G, about 21 k for a 40 × 40 Cholesky solve, then 7 complex 4 × 4 inversions. It needs floating point or careful wide fixed point.
  • This is the block to drop if area or schedule is tight. If you keep it, a soft processor (MicroBlaze) or an HLS block is far quicker to get right than hand-written RTL.
4

8-bit quantizer

both
What it does

Every feature has a known typical range, taken from the training data's 1st and 99th percentiles. This stage clips each feature to its range and maps it onto 0–255, so the classifier only has to multiply 8-bit numbers.

Exact maths 
q_i = round( clip( (x_i − lo_i) / (hi_i − lo_i), 0, 1 ) · 255 )      i = 1 … 16
    = clamp( round( (x_i − lo_i) · s_i ), 0, 255 ),   s_i = 255 / (hi_i − lo_i)
rounding: numpy rounds exact halves to the nearest EVEN integer (2.5 → 2, 3.5 → 4)
Hardware notes
  • Per feature: one subtract, one multiply by a stored constant, round, clamp. Sixteen per trial.
  • 15 of 16 features can be negative, so everything before this stage is signed. The output is unsigned 0–255.
  • Any constant you folded in step 3 (dropping ÷N, using log₂, dropping filter gain) moves lo and hi by the same transform. Update both bounds and nothing else changes.
  • Half-to-even rounding affects only exact ties, which are rare. Matching it keeps the golden-model comparison clean.
5

Linear layer: three scores

both
What it does

Each pain level has 16 weights and one bias. Its score is each 8-bit feature times its weight, added up, plus the bias.

Exact maths 
score_k = bq_k + Σ_i Wq[k][i] · q_i          k = 0 Low, 1 Moderate, 2 High
                                            48 multiply-adds, 3 bias adds
Weights for 8-bit inputs, derived from the exported float weights:
    Wq[k][i] = W_eff[k][i] · (hi_i − lo_i) / 255
    bq_k     = b_eff[k] + Σ_i W_eff[k][i] · lo_i
Hardware notes
  • One MAC unit looping 48 times is plenty, or 3 MACs running 16 cycles each.
  • The weights are still floating point. Wq ranges from about 10⁻⁵ to 3 × 10⁻³ in the fixed variant. Multiply every Wq and bq by the same power of two before rounding to integers. A shared scale never changes which score is biggest. Pick the bit width with the golden model.
  • Make the weights, biases and quantizer bounds loadable (registers or BRAM initialized from a file), not hard-coded. They will change if the model is retrained (see the reference-electrode risk below). With loadable values, retraining needs no RTL change.
  • Optional per-user calibration adds 3 numbers to the biases after a short setup session. Writable bias registers are all it needs.
6

Decision

both
Exact maths 
class = index of the largest score          (ties go to the LOWER index, as numpy argmax)
  0 = Low       rating below 4
  1 = Moderate  rating 4 to below 7
  2 = High      rating 7 or above

Severe-pain model (yes/no): its "no" row is all zeros, so only one score exists.
  severe = (s > 0),   s = bq_1 + Σ_i Wq[1][i] · q_i    (s = 0 → not severe)
Hardware notes
  • Two comparators and a 2-bit output register.
  • If the device should also offer the severe yes/no output, it is a second set of 16 weights plus 1 bias, using the same MAC and the same features. Its weights are in the JSON under severe__fixed and severe__no_mvar.

Gaps between the training data and a real headset

1. Reference electrode: the biggest open risk.

Every training recording was re-referenced to the average of 32–64 electrodes (checked in the file headers of all 9 datasets). A 3- or 4-electrode headset cannot compute that average. The software side has to retrain with a reference the headset can actually produce, and that will change the weights. The RTL is unaffected as long as weights and bounds are loadable (step 5).

2. Artifact cleaning.

The training data had blinks and muscle noise removed by ICA before any feature was computed. The device has none of that, so a simple trial-rejection rule (for example, an amplitude limit) needs to be specified and added, either in the capture stage or as a "no answer" flag.

3. Units and timing.

Features assume µV and a laser onset accurate to about a millisecond. The ADC scale and the trigger path both need to be pinned down early.

Suggested build and test order

  1. Golden model first. Write a Python model that does the RTL's fixed-point arithmetic exactly, stage by stage, and check its class output against the float model on the validation set.
  2. Test vectors from real trials. For a few hundred validation trials, dump the raw epoch, the filter outputs, the 16 features, the 16 codes, the 3 scores and the class. The testbench compares each stage separately, so a mismatch points at one block.
  3. Build back to front. Linear layer and argmax first (smallest, and testable from the dumped codes), then the quantizer, then the feature units, then the filter engine and buffer.
  4. Replace the old RTL. The current RTL/ modules (alpha/beta/theta thresholds and sigmoid_cell.v) belong to the old designs and don't match this model.
